# Disk / gin_cpp 实测基线（2026-11-19）

已完成框架 HTTP、真实业务查询及 1 MiB 文件传输的三轮短时采样。框架和查询结果可作为当前版本的本机性能基线；并发上传发现真实失败，不能据此宣称整个系统已通过可靠性验收。

## 测试条件

- CPU：Intel Core i7-12800HX，24 个逻辑处理器；物理内存约 15.7 GiB；Windows 11。
- Disk：`438c7b06ab8414969746240c8aef52aff2e8b9e2`（`cpp-backend-gin`），源码工作树干净。
- gin_cpp：`a1e0491b0b373c3e6cbd786e1f48577b20680826`，源码工作树干净。
- API、框架和 WSL 存储节点为 Release 构建；API 链接的本机 gRPC/Protobuf 静态依赖为 Debug 构建。
- 负载端与 API 同机，存储位于 Ubuntu WSL，采用回环网络；2 个 I/O 线程，普通业务池 4 线程。
- HTTP/API 每场景先预热 2 秒，再测 3 轮、每轮 10 秒。文件场景不单独预热，包含首次传输、客户端哈希与同步清理开销。
- API 数据集为 4 个账号，每账号 100 个目录及初始化文件；每轮使用同一个本轮测试库，轮次间不清空缓存。
- MouduAsio 使用本地网络头文件修改；实际源码哈希和网络补丁均已保留，不能仅凭依赖仓库 HEAD 复现。

## 正确性与已知问题

- CTest：Disk 的 gin_router、disk_transport、gin.runtime 三项通过；独立基准注册的 gin.runtime 通过。
- 业务回归：测试副本完整通过过一次，包括 bcrypt 兼容、二进制/分块上传、配额竞争、移动防循环和共享对象引用。随后同版本复测在非法上传声明的提前拒绝处出现连接重置，已保留通过和失败记录。
- API/文件性能采样显式使用 `--skip-integration`，复用同版本通过记录；该参数不代表忽略已知的间歇性失败。
- 文件负载共记录目标失败 83 次、清理失败 0 次。相同内容上传与物理文件删除之间存在唯一索引/主键锁顺序冲突，MySQL 死锁被映射为 HTTP 503。
- 测试副本只适配 HTTP 头大小写和日志 PIPE 消费，保留全部原业务断言；网络与业务源码未因测试改写。

## 简历表述建议

gin_cpp 可写：搭建可复现 HTTP 基准，在 i7-12800HX 同机回环、16 VU、三轮 10 秒负载下，固定文本成功吞吐中位数约 4.02 万次/秒，P99 约 1.51 ms；保留多轮波动、响应校验和进程资源采样。

Disk 可写：构建真实 MySQL＋gRPC 全链路压测，验证下载字节与 SHA-256、负载后配额和对象引用，并定位同内容上传与永久删除并发时的数据库死锁。

当前不宜写“并发上传零失败”“已解决死锁”或“达到生产容量上限”。修复后应按相同环境另建一轮结果，比较失败率和吞吐，不覆盖本轮证据。
